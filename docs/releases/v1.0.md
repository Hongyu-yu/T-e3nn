# T-e3nn v1.0

This GitHub release fixes tensor-product weight handling and higher-order
derivatives, and improves selected generated tensor-product graphs while
preserving time-reversal and spatial symmetry contracts. The GitHub tag is
`v1.0`; the Python distribution/import version remains **`e3nn==0.5.0+spin`**
to preserve existing SpinGNN compatibility checks. This is not an upstream
e3nn 1.0 release or a PyPI publication.

## Correctness and compatibility

- Fix instruction weight-view offsets when weighted and unweighted paths are
  mixed. Preserve structured and legacy flattened per-path weight lists,
  multiple broadcast batch dimensions, and empty lists for tensor products
  without weighted paths.
- Reject NaN/Inf equivariance errors and nonfinite or negative tolerances before
  evaluating the model. Preserve zero tolerance and dtype-dependent defaults,
  and report the spin/time-reversal transformations involved.
- Keep normalized spherical-harmonic second derivatives finite at zero input,
  preserving the existing normalization threshold and nonzero-vector algorithm.
- Include the existing `nn.models.v2203` sparse voxel module in built packages.
  Fix test default-dtype leakage, trusted serialization roundtrips on modern
  PyTorch, and fork-specific doctest representations.

Parameter ordering, checkpoint state, normalization, time-reversal labels and
FP32/FP64 contracts are preserved. Existing TorchScript/PT2 deployment artifacts
contain generated graphs: rebuild them with the intended dependency and the
same configuration/learned state to use these changes. CUDA PT2 artifacts must
be built and validated for the target architecture.

## Retained generator improvements

- Select valid weighted `u<vw` channel pairs before forming the outer product.
- Specialize scalar-input and scalar-output `uvuv` contractions with the stored
  Wigner coefficients, preserving dtype-conversion rounding.
- Split per-sample weighted `uvu` weights once and balance contiguous equal-width
  output groups for the validated pattern: every path has unit second-input
  multiplicity and the output is completely populated. Pure-scalar outputs,
  shared/unweighted paths and unsupported patterns keep their original graph.

Unweighted triangular preselection and all-scalar `uvu` grouping were rejected
and are not included. SpinGNN node spherical-harmonic reuse and targeted Trainer
backward experiments were also rejected; they do not contribute to the results
below. Source-bound benchmarks and regression tests are included.

## Validation and measured scope

The complete T-e3nn suite reports **2474 passed, 40 skipped and 14 existing
expected failures**. The built and installed wheel's 64 Python files match the
validated runtime source. Pinned formatting/lint and the corresponding
numerical, higher-order gradient and deployment checks passed. The validated
integration stack uses PyTorch 2.11.0 with CUDA 12.8; these results do not certify
every dependency version permitted by package metadata.

Release CI is aligned to CPython 3.10.20/PyTorch 2.11.0 CPU, with pinned
numerical/test dependencies and matching binary PyG extensions. It preserves
the complete tests, package doctests and benchmark contracts, and runs the
four existing example doctests separately from executable data generators.
The earlier full-suite count used a CUDA-build Torch wheel with CUDA disabled;
the GitHub CPU-wheel result is a separate validation, not implied by that count.

For one fixed, complete SpinGNN NequIP SOC eager-training workload—FP32,
128 atoms, 3408 edges, two frames, width 16 and two layers—the measured changes
relative to the original T-e3nn source are:

| Metric | RTX 4090 | RTX 5090 |
| --- | ---: | ---: |
| Training throughput | +88.85% | +49.64% |
| Device process memory | +1.93% | +1.76% |
| Host RSS | -0.18% | -0.42% |

Each card used five independent-process AB/BA pairs, 20 warmup steps and five
measured blocks of 200 steps per process. Every pair was faster. The step
includes energy, forces, spin forces, stress, loss backward, finite checks and
AdamW updates. This workload trades a small device-memory increase for higher
throughput; it does not show a peak-device-memory reduction. An isolated large
weighted-triangular second-derivative benchmark also improved, but it is not an
atom-count or molecular-dynamics throughput result.

The fixed eager comparison attributes its gain to T-e3nn. It does not establish
a compiled full-FX or LAMMPS speedup. Final-source CUDA full-FX correctness and
fresh two-card NequIP TorchScript/PT2 Python, serial LAMMPS and two-rank MPI
comparisons passed with the original tolerances. Allegro's main contractions
use its own strided implementation; these results do not imply the same gain
for Allegro, other models, other shapes or unmeasured GPUs such as H100.

## Stability and runtime limits

Default-policy host-memory failures remain visible: the 4090 NequIP training
long run, the original 4090 Allegro SOC/PT2 deployment run, and a later 5090
NequIP TorchScript deployment run fail their original growth gates. The 5090
default PT2 deployment route passes. GPU memory growth alone is not the host
memory acceptance criterion.

Separate, explicitly selected Linux process-local THP-disable configurations
pass the original 4090 training memory gates and all five tested deployment
routes, each with 10000 measured steps. The matched training control preserves
all 98 final model/AdamW tensors byte-for-byte. Complete deployment physical
outputs match their default-policy serial references exactly. These settings
leave the parent process and node-wide policy unchanged and are not enabled
automatically by T-e3nn. Their passing results do not overwrite default-policy
failures; the Allegro control used a different physical 4090 from its original
failure. No additional deployment speed benefit is claimed.

The separate five-pair 4090 THP-policy comparison passes median nonregression
limits, but two BA pairs are slower by 10.54% and 11.45%; its original
additional-speed-benefit verdict remains rejected. Do not interpret the
runtime setting as a universal performance improvement. Precision, physical
definitions, numerical tolerances, memory gates and rejected measurements were
not relaxed or removed.

The review also retains the historical ELEMENTA failures and distributed-test

or its default configurations passed every test.

## Release boundary

The inherited PyPI-upload job is restricted to the upstream `e3nn/e3nn`
repository. Publishing this fork's GitHub release therefore does not upload an
`e3nn` package to PyPI. Install from the reviewed `v1.0` tag in a private
environment with the required PyTorch stack, and verify the actual source
revision rather than relying on the unchanged `0.5.0+spin` compatibility label.
